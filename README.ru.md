# Скилл для виджетов Telegram

[English](README.md) · **Русский**

Скилл для ИИ-агентов (Claude Code, приложения Claude, OpenAI Codex и другие), который учит их правильно
и безопасно делать **виджеты Telegram Bot API 10.4**: интерактивные HTML-блоки, которые бот присылает
прямо в сообщении.

Скилл не привязан к языку и фреймворку. Серверная часть сводится к обычным HTTPS-запросам к Bot API,
поэтому подходит для ботов на Python, Node.js, Go, PHP, Java и чём угодно ещё. Готовые адаптеры есть для
Python (aiogram и чистая стандартная библиотека), Node.js и curl.

Сам скилл написан на английском, чтобы им могли пользоваться все.

## Зачем он нужен

Виджеты новые и необычные. HTML работает в песочнице QuickJS без сети, должен уместиться в **4096 байт
после сжатия zlib**, не может сам менять своё состояние, отправляет боту запросы до 64 байт только по
тапу и рисуется движком Telegram, а не браузером. Большинство ошибок видно только в настоящем Telegram.
В скилл собраны официальные правила и уроки внедрения настоящего виджета в продакшен-боте (редактор
«кадр и минута» с живым кольцом прогресса для бота, который делает видеокружки). В том числе ошибки,
которых не было видно в браузере:

- путь на canvas, который в Chrome выглядел нормально, а в Telegram рисовал полосу через картинку;
- запросы, отклонённые с `BUSY`, когда человек нажимал кнопку сразу после касания;
- таймаут скачивания в 30 секунд в библиотеке, из-за которого один и тот же файл то проходил, то нет;
- сырой текст ошибки, через который пользователю мог уйти **токен бота** из сообщения HTTP-клиента;
- блокировка очереди пользователя, пока бот ждёт, что человек выберет.

## Что получает агент

```
skills/telegram-widgets/
├── SKILL.md                    # порядок работы агента (6 шагов)
├── references/
│   ├── platform.md             # методы, поля, лимиты, разрешённые HTML/CSS/JS, API TelegramWidget
│   ├── security.md             # модель угроз и чек-лист безопасности перед выпуском
│   ├── pitfalls.md             # 19 проверенных на практике ошибок: признак, причина, исправление
│   ├── server-side.md          # архитектура серверной части в псевдокоде (любой язык)
│   ├── frameworks.md           # обходные пути для aiogram, python-telegram-bot, grammY, Telegraf и других
│   ├── patterns.md             # живой прогресс, редактор с автозапуском, опрос, тикер, бюджет картинки
│   └── testing.md              # проверка размера, локальный просмотр, чек-лист живого теста
├── templates/
│   └── widget-skeleton.html    # безопасная заготовка виджета
├── adapters/
│   ├── python-aiogram.py       # методы, middleware и хранилище состояния для aiogram 3.x (проверено вживую)
│   ├── python-stdlib.py        # без зависимостей
│   ├── node-fetch.mjs          # Node 18+ / Deno / Bun, без зависимостей
│   └── curl.md                 # тела HTTP-запросов для любого языка
└── scripts/
    ├── check_widget.py         # размер так, как его считает сервер, и проверка запрещённых функций
    └── preview_widget.py       # локальный просмотр в браузере с заглушкой TelegramWidget
```

По скиллу агент действует так. Проверяет, где виджеты доступны (в продакшене только в личке с ботом).
Сначала проектирует протокол состояния и запросов, потом планирует бюджет в 4 КБ. Собирает виджет из
безопасной заготовки. Подключает серверную часть: проверку владельца, строгий разбор запросов,
ограничение частоты правок, запасной путь. И проверяет всё в настоящем Telegram, прежде чем сказать, что
готово.

## Установка

### Claude Code

```bash
git clone https://github.com/aislam23/telegram-widgets-skill.git
mkdir -p ~/.claude/skills
cp -r telegram-widgets-skill/skills/telegram-widgets ~/.claude/skills/
```

Чтобы скилл работал только в одном проекте, скопируйте папку в `<проект>/.claude/skills/`. Скилл
подключается сам, когда в задаче речь идёт о виджетах Telegram или интерактивных сообщениях бота.

### Приложения Claude (claude.ai, десктоп)

Скачайте `telegram-widgets.zip` из
[последнего релиза](https://github.com/aislam23/telegram-widgets-skill/releases/latest) и загрузите его
как свой скилл в настройках скиллов приложения.

### OpenAI Codex CLI

```bash
mkdir -p ~/.codex/skills
cp -r telegram-widgets-skill/skills/telegram-widgets ~/.codex/skills/
```

Если ваша версия Codex не поддерживает скиллы, добавьте в `AGENTS.md` проекта строку:
`For Telegram widgets, follow skills/telegram-widgets/SKILL.md and the files it references.`

### Другие агенты (Cursor, Gemini CLI, Windsurf и так далее)

Скопируйте папку `skills/telegram-widgets` в репозиторий и укажите на `skills/telegram-widgets/SKILL.md`
в файле правил агента (`AGENTS.md`, `.cursor/rules`, `GEMINI.md`).

## Как пользоваться

Просто опишите задачу, скилл подключится сам:

- «Сделай в моём видеоботе живой прогресс вместо сообщения "Обрабатываю..."»
- «Сделай виджет-опрос для бота на Go, чтобы результаты обновлялись у всех»
- «Мой виджет в браузере работает, а в Telegram выглядит сломанным»
- «Перенеси меню настроек на кнопках в виджет, бот на grammY»

Инструменты можно запускать и самому:

```bash
python3 skills/telegram-widgets/scripts/check_widget.py my-widget.html
python3 skills/telegram-widgets/scripts/preview_widget.py my-widget.html \
        --chat-data '{"m":"p","p":40}' --out preview.html --dark
```

## Актуальность и точность

- Написано под **Telegram Bot API 10.4** (ноябрь 2026), профиль виджетов 1.
- Проверено вживую в Telegram: `sendWidget`, `editMessageWidgetData`, `editMessageCaption` у виджета,
  `deleteMessage`, доставка `widget_query` и ответы через aiogram 3.20, исправление canvas и очередь
  запросов.
- Взято из официальной документации и вживую не проверялось: группы, inline-режим, пересылка и общие
  виджеты (на момент написания только на тестовом сервере), оплата через кошелёк TON и примеры для
  фреймворков, кроме aiogram. В файлах это отмечено.
- Виджеты выкатываются по шагам. Если в официальной документации написано что-то новее, верна она.

Официальная документация: [гайд по виджетам](https://core.telegram.org/bots/widgets) ·
[Bot API](https://core.telegram.org/bots/api) · [список изменений](https://core.telegram.org/bots/api-changelog)
